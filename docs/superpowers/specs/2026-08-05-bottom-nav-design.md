# 하단 내비게이션 개편 설계

날짜: 2026-08-05
대상: `C:\Pcall\Trip` (범용 여행앱, 1단계 완료 상태)

## 배경

1단계로 오사카 전용 대시보드가 범용 여행앱이 됐다. 지금 여행 화면은 위에서
아래로 한 줄이다:

```
요약 헤더 → 일차 탭 → 타임라인 → 아코디언 6개(라피트·숙소·준비물·현지 경비·경비 내역·팁)
```

아코디언은 `trip.sections` 배열을 순회해 그린다. 내장 4개(숙소·준비물·현지
경비·경비 내역)도 `type:"builtin"`으로 그 배열에 들어 있는데, **오사카 원본의
아코디언 순서를 데이터로 재현하려는 목적**이었다.

문제는 이 구조가 길다는 것이다. 경비를 적으려면 타임라인을 다 지나 스크롤해
내려가서 아코디언을 열어야 한다. 현지에서 계산대 앞에 서서 할 동작이 아니다.

## 요구사항 (브레인스토밍 확정)

- **하단 내비게이션으로 화면 전체를 전환한다.** 탭을 누르면 본문이 그 화면으로
  바뀐다. 일반적인 모바일 앱 구조
- **탭 다섯 개 고정**: 일정 · 숙소 · 준비물 · 경비 · 정보
- **현지 경비와 경비 내역을 '경비' 한 화면으로 합친다.** 둘 다 돈이고, 탭
  구조에서는 나눌 이유가 없다
- **사용자가 만든 섹션(라피트 시간표·팁)은 '정보' 탭에 모은다.** 2단계 섹션
  편집기가 여기에 붙는다
- 요약 헤더는 모든 탭에서 유지한다 (여행 정체성 + D-day + 날씨 + 경비 합계)

## 화면 구조

```
┌──────────────────────┐
│  오사카 여행    ⚙ 편집 │  요약 헤더 — 모든 탭 공통
│  D+2 · 6박7일        │
├──────────────────────┤
│                      │
│   선택된 탭의 내용      │
│                      │
├──────────────────────┤
│ 🗓  🏨  🎒  💰  ℹ️  │  하단 내비 (position:fixed)
│ 일정 숙소 준비물 경비 정보│
└──────────────────────┘
```

| 탭 | 내용 |
|---|---|
| 🗓 일정 | 일차 탭 스트립 + 타임라인. **일차 스트립은 이 탭에서만 보인다** |
| 🏨 숙소 | `trip.hotel` |
| 🎒 준비물 | 체크리스트 (`renderPacking`) |
| 💰 경비 | 위: 현지 경비 입력·합계·목록 (`renderSpend`) / 아래: 출발 전 결제 내역 (`expensesTableHtml`) |
| ℹ️ 정보 | 사용자 섹션(`text`/`list`/`table`)을 아코디언으로 |

`편집` 토글은 일정 탭에서만 노출한다 — 다른 탭에서는 할 일이 없다. `⚙`(여행
설정)은 모든 탭에서 유지한다. 위 그림의 헤더 우측은 일정 탭 기준이다.

**빈 상태.** 새로 만든 여행은 사용자 섹션이 없으므로 정보 탭이 비어 있다. 새
여행의 준비물·경비도 마찬가지다. 각 탭은 비었을 때 무엇을 하면 되는지 한 줄로
안내한다 — 1단계 리뷰가 "새 여행의 첫 일차가 아무 단서 없는 빈 카드"라고 지적한
것과 같은 부류다. 정보 탭은 2단계 섹션 편집기가 붙기 전까지 "여행 설정에서 메모나
표를 추가할 수 있습니다" 대신 **지금 할 수 있는 게 없다는 사실을 그대로** 적는다
(예: "라피트 시간표처럼 직접 만드는 항목이 여기 표시됩니다"). 없는 기능을
가리키는 안내는 쓰지 않는다.

여행 목록(`#screen-list`)과 여행 설정(`#screen-edit`)에는 하단 내비를 그리지
않는다.

## 데이터 모델 변경

`sections`에서 `type:"builtin"` 항목을 제거하고, **사용자 정의 섹션만 담는
배열**로 바꾼다. 탭 다섯 개는 코드에 고정한다.

```js
// 전
sections: [
  { id:"s_rapit", icon:"🚄", title:"라피트 시간표", type:"table",   body:[…] },
  { id:"s_hotel", icon:"🏨", title:"숙소",         type:"builtin", body:"hotel" },
  { id:"s_packing", …                              type:"builtin", body:"packing" },
  { id:"s_spend", …                                type:"builtin", body:"spend" },
  { id:"s_expenses", …                             type:"builtin", body:"expenses" },
  { id:"s_tips",  icon:"💡", title:"팁",           type:"list",    body:[…] }
]

// 후 — 정보 탭에 이 순서로 그려진다
sections: [
  { id:"s_rapit", icon:"🚄", title:"라피트 시간표", type:"table", body:[…] },
  { id:"s_tips",  icon:"💡", title:"팁",           type:"list",  body:[…] }
]
```

**근거:** 내장 항목을 배열에 넣은 유일한 이유가 아코디언 순서를 데이터로
결정하기 위함이었는데, 탭이 되면서 그 요구가 사라졌다. 그대로 두면 아무도 읽지
않는 데이터가 남고, 2단계 섹션 편집기가 "이건 편집되는데 저건 안 되는" 목록을
다루게 된다.

마이그레이션: 기존 여행의 `sections`에서 `type === "builtin"` 항목을 제거한다.
`schema.js`의 `defaultSections()`는 빈 배열을 돌려준다. `sample-trip.js`도
`convert_sample.py` 없이 직접 갱신한다 (`data.js`는 이미 삭제됐다).

## 라우팅

기존 해시 라우터를 확장한다.

| 해시 | 화면 |
|---|---|
| `#/t/<id>` | 일정 탭, 오늘(또는 첫/마지막) 일차 |
| `#/t/<id>/d/<n>` | 일정 탭, n일차 |
| `#/t/<id>/hotel` | 숙소 탭 |
| `#/t/<id>/packing` | 준비물 탭 |
| `#/t/<id>/money` | 경비 탭 |
| `#/t/<id>/info` | 정보 탭 |

뒤로가기로 탭 이동이 되돌아가고, 특정 탭 링크를 공유할 수 있다.

## 렌더 범위

`showTrip`은 이미 "여행을 여는 것"과 "일차를 바꾸는 것"을 구분한다(1단계 리뷰가
두 번 되돌린 지점 — 전체를 다시 그리면 열어둔 아코디언이 닫히고 입력 중이던
경비가 날아간다). 탭 전환도 같은 규율을 따른다:

- **여행 열기** — 헤더 + 하단 내비 + 선택 탭 본문
- **탭 전환** — 본문과 내비의 선택 표시만. 헤더는 그대로
- **일차 전환** — 일차 스트립과 타임라인만 (현행 `showDay` 그대로)

경비 탭에서 금액을 입력하다 다른 탭에 갔다 오면 입력이 사라지는 것은 받아들인다
(탭이 바뀌면 그 화면은 실제로 사라진 것이므로). 하지만 **같은 탭 안에서의 동작이
입력을 날리면 안 된다** — 예를 들어 경비를 하나 추가한 뒤 목록만 다시 그려야지
화면 전체를 다시 그리면 안 된다.

## CSS

- 하단 내비는 `position:fixed; bottom:0`, `padding-bottom:env(safe-area-inset-bottom)`
  — 아이폰 홈 인디케이터에 가려지지 않게
- 본문에 `padding-bottom`으로 내비 높이 + safe-area만큼 여백. 안 주면 마지막
  항목이 바 뒤에 잘린다
- 일차 탭 스트립의 `position:sticky; top:0`는 유지

## 검증

1. **순수 함수** — builtin 제거 마이그레이션(정상/이미 제거됨/섹션 없음), 탭
   해시 파싱(정상/미지의 탭/잘못된 형식)
2. **오사카 회귀** — 라피트·팁이 정보 탭에, 숙소·준비물·경비가 각 탭에.
   내용은 개편 전과 동일
3. **탭 이동** — 다섯 탭을 오가며 헤더가 다시 그려지지 않는지, 뒤로가기가 탭을
   되돌리는지
4. **경비 입력 보존** — 경비 탭에서 금액을 입력하고 항목을 추가해도 다른 입력이
   유지되는지
5. **일정 탭** — 일차 전환과 편집 모드가 1단계와 동일하게 동작하는지
6. **실기기** — 아이폰에서 홈 인디케이터에 바가 가려지지 않는지, 마지막 항목이
   잘리지 않는지

## 하지 않는 것

- 탭바 아이콘을 SVG로 교체 (이모지 유지 — 이 앱의 기존 방식)
- 탭 순서·표시 여부 사용자 설정
- 스와이프로 탭 전환 (2단계 이후 고려)
- 사용자 섹션을 탭으로 승격하는 기능
- 2단계 항목(일차별 도시·통화, 환율, 섹션 편집기, 이미지 첨부)
