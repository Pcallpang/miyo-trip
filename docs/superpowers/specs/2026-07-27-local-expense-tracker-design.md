# 현지 경비 기록 기능 설계

날짜: 2026-07-27
대상: `C:\Pcall\Trip` (오사카 여행 PWA, https://pcallpang.github.io/osaka-trip/)

## 배경

기존 "💰 경비 내역" 아코디언은 **출발 전 이미 결제한 고정비**를 보여준다 — 항공권·숙소·USJ 티켓·버스투어 등 12건, 전부 원화, `data.js`에 하드코딩된 읽기 전용 표(합계 2,612,367원).

여기에 **여행 중 현지에서 쓰는 돈**을 기록하는 기능을 추가한다. 성격이 완전히 달라 기존 표와 섞지 않고 별도 영역으로 만든다.

## 요구사항

브레인스토밍에서 확정한 내용:

| 항목 | 결정 |
|---|---|
| 목적 | 뭐에 얼마 썼는지 **기록** (예산 잔액 추적 아님) |
| 화폐 | **엔화 입력 + 원화 병기**, 환율은 사용자가 설정 |
| 입력 필드 | 금액 + 내용 + 분류 (날짜는 자동) |
| 사용자 | **한 사람이 도맡아 기록** — 기기 간 동기화 불필요 |
| 배치 | 하단 아코디언 + 상단 요약에 합계 노출 |

## 화면

### 상단 요약 (`renderSummary`)

기존 총 경비 줄 뒤에 이어 붙인다. 좁은 화면에서는 다음 줄로 넘어간다.

```
💰 총 2,612,367원 (2인) · 💸 현지 ¥12,340 (약 111,060원)
```

**기록이 1건 이상일 때만 표시한다.** 출발 전 계속 ¥0이 뜨는 것을 피하기 위함.

### 하단 아코디언 "💸 현지 경비"

`#fixed` 안, "🎒 준비물" 바로 다음에 `<details>`로 추가한다. 펼쳤을 때 위에서부터:

1. **합계** — `¥12,340` (약 111,060원)
2. **분류별 합계** — 칩 형태, 지출이 있는 분류만: `식비 ¥8,200` `교통 ¥2,140` `쇼핑 ¥2,000`
3. **입력 폼** — `[금액 ¥] [내용] [분류▾] [추가]`
4. **목록** — 날짜별 그룹, 최신 날짜가 위. 같은 날 안에서는 나중에 추가한 것이 위. 각 줄 오른쪽에 삭제 `×`
5. **환율 설정** — `100엔 = [900]원`

분류는 **식비 / 교통 / 쇼핑 / 관광 / 기타** 5개 고정.

## 데이터

### 저장 위치

기존 `store` 래퍼(localStorage, 접두사 `osaka-trip:v1:`)를 그대로 쓴다. `data.js`는 수정하지 않는다.

이 분리가 중요하다 — 일정을 수정해 재배포해도 기록한 경비는 지워지지 않는다. 준비물 체크 상태가 유지되는 것과 같은 원리다.

### 키 구조

**`spend`** — 지출 항목 배열:

```js
[
  { id: 1785000000000, date: "2026-07-29", jpy: 1200, cat: "식비", note: "이치란 점심" }
]
```

- `id`: `Date.now()` 기반. 같은 밀리초 충돌은 실질적으로 불가능하나, 삭제 시 id로 필터링하므로 중복되면 두 건이 함께 지워진다. 추가 시 기존 id와 겹치면 1씩 증가시켜 회피한다.
- `date`: 추가 시점의 로컬 날짜 `YYYY-MM-DD`
- `jpy`: 정수 (엔화는 소수점을 쓰지 않음)

**`fx`** — 100엔당 원화. 기본값 **900**.

### 원화 환산

```
원화 = round(엔화 합계 × fx / 100)
```

항목별로 환산하지 않고 **합계에만** 적용한다. 항목마다 원화를 병기하면 목록이 빽빽해지고, 어차피 환율이 근사값이라 정밀도에 의미가 없다.

## 동작

추가·삭제·환율 변경 시 모두 같은 흐름을 탄다:

```
사용자 입력 → localStorage 저장 → renderSpend() 다시 그림 → renderSummary() 다시 그림
```

`renderSummary`는 현재 `meta`만 인자로 받는다. 현지 합계를 반영해야 하므로 함수 안에서 `store.get("spend")`를 직접 읽도록 고친다 — 인자를 늘리는 것보다 호출부 변경이 적다.

## 예외 처리

| 상황 | 처리 |
|---|---|
| 금액이 비었거나 숫자가 아님 | 추가하지 않음, 입력칸에 포커스 |
| 금액이 0 이하 | 추가하지 않음 |
| 내용이 비었음 | 허용. 목록에 분류명을 대신 표시 |
| 환율칸이 비었거나 0 | 원화 병기만 생략, 엔화는 그대로 표시 |
| localStorage 용량 초과 | 기존 `store.set`의 try/catch가 삼킴 (기존 동작 유지) |
| 저장된 데이터가 배열이 아님 | 빈 배열로 폴백 |

사용자 입력 문자열(`note`)은 기존 `escHtml`로 이스케이프해 삽입한다.

## 범위 밖 (YAGNI)

- **항목 수정** — 삭제 후 재입력으로 갈음. 수정을 넣으면 입력 UI가 두 배가 된다
- **예산 설정·잔액 표시** — 목적이 기록이라고 확정됨
- **기기 간 동기화·내보내기** — 한 사람이 기록하기로 확정됨
- **결제수단(현금/카드) 구분** — 입력 부담 대비 이득이 적음
- **실시간 환율 조회** — 오프라인 동작을 깨뜨림

## 영향 범위

| 파일 | 변경 |
|---|---|
| `app.js` | `renderSpend()` 신규, `renderFixed()`에 아코디언 추가, `renderSummary()` 수정 |
| `styles.css` | 합계 카드·분류 칩·입력 폼·목록 스타일 |
| `sw.js` | 캐시 버전 `v5` → `v6` |
| `data.js` | **변경 없음** |
| `osaka-trip.html` | `bundle.py`로 재생성 |

## 검증

배포된 주소에서 실제로 확인한다:

1. 항목 추가 → 목록·합계·분류별 칩·상단 요약에 반영되는가
2. 새로고침 후에도 남아 있는가
3. 삭제가 해당 항목만 지우는가
4. 환율 변경이 원화 병기에 즉시 반영되는가
5. 잘못된 입력(빈 금액, 문자, 음수)이 거부되는가
6. 기록 0건일 때 상단에 "💸 현지"가 뜨지 않는가
7. 오프라인에서 열리고 기록이 보이는가
